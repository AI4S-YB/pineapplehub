# 裁剪圆柱近似：来源、实际变换与测量边界

审查日期：2026-10-19。源码基线：`9ed497db0e2e3f0c030d0c7733d3f2bb44addcff`。本次核对公式、调用链和历史实现，没有修改计算代码，也没有重新测量实物。

结论：现有方法是**以扶正果体裁剪图为尺度的固定形变近似**。它有明确来源和可解释的效果，值得保留为经验基线；不能因没有使用真实焦距就否定，也不能把它描述成已经标定的通用三维恢复。项目负责人已报告许多实物对照结果接近实测，主要失败来自前置识别；本次没有独立复核这些样本，以下数值均为公式推导，不是新的实测精度报告。

## 1. 来源与传承

找到与实现逐项吻合的来源：Hammer 于 2012 年回答的 [Warp Image to Appear in Cylindrical Projection](https://stackoverflow.com/questions/12017790/warp-image-to-appear-in-cylindrical-projection)。其示例包含相同的 `f = w`、`r = w`、圆心位置、二次方程正根及双线性取样。

该回答处理的是把平面图像投到凹圆柱面，再形成透视图的图形变换。它为避免空洞，从输出像素反查输入位置；这里的“反向取样”不能直接解释成“真实凸果体的逆透视解”。这是原问题的边界，并不直接否定将该形变用于经验校正。

仓库历史也保留了传承证据：

- `2a000707fbf4d9d9629b27e4ac12d592dd5b16b2`（2025-04-08，`fix: distortion (#14)`）加入 `archive/convert_pt.cpp`、Python `convert_pt()` 和 `unwrap()`；C++ 与上述回答的核心计算一致。
- 同一提交的 `main.py` 先用外接矩形扶正裁剪，再传入 `unwrap()`，随后旋转 90° 重复处理。裁剪不是后来才加上的解释。
- Rust 提交 `a1b780e`（2026-03-02）的注释明确对齐 Python `convert_pt`。当前版本保留该几何关系，将逐列不变量提前计算。

## 2. 当前到底用了哪个宽度

[普通路径](../../src/pipeline/unwrap_metrics.rs) 与[并行路径](../../src/pipeline/fast.rs) 都经过：

`识别果体范围 → 映射回高分辨率 → 扶正 → 紧裁剪 → unwrap`

设最终裁剪图尺寸为 `W_roi × H_roi`：

| 分支 | 传入图像 | `f`、`r` 的值 | 后续主要用途 |
| --- | --- | --- | --- |
| 竖向 | 扶正的果体裁剪图 | `W_roi` | 高度估计 |
| 横向 | 同一裁剪图旋转 90° | `H_roi` | 宽度、轮廓及体积／表面积估计 |

这里既不是整张原照片的宽度，也不是为了旋转而临时扩大的对角线方框宽度。`f`、`r` 是虚拟几何参数；原照片焦距、拍摄距离和实际半径没有从这一步求出来。

物理单位来自另外的硬币尺度。低分辨率的每毫米像素数乘以高低分辨率比例，再用于高分辨率结果；像素归一化与毫米校准是两件事。

## 3. 从当前代码化简出实际形变

以下由 [correction.rs](../../src/correction.rs) 独立化简。令传入图宽为 `W`、高为 `H`，输出像素的中心化坐标为

\[
X=x-W/2,\quad Y=y-H/2,\quad t=X/W.
\]

默认参数为 `f = r = W`，故圆心深度为

\[
z_0=W-\sqrt{W^2-(W/2)^2}=aW,
\qquad a=1-\frac{\sqrt3}{2}\approx0.1339745962.
\]

射线满足 `X_c = X z_c / f`，圆柱截面满足

\[
X_c^2+(z_c-z_0)^2=r^2.
\]

代入得到代码求解的二次式：

\[
(1+t^2)z_c^2-2z_0z_c+z_0^2-r^2=0.
\]

取代码的正根，并除以 `f = W`，得到纯粹依赖相对横向位置的函数：

\[
k(t)=\frac{z_c}{f}
=\frac{a+\sqrt{1+(1-a^2)t^2}}{1+t^2}.
\]

程序读取的输入位置是

\[
x_s=W/2+k(t)X,\qquad y_s=H/2+k(t)Y.
\]

注意这是“输出位置 → 输入取样位置”。`k > 1` 表示从更外侧取样，结果中的对应位置向中心收缩，不是把中心放大。

| 输出列距中心占全宽的比例 `abs(X)/W` | 输入取样比例 `k` | 该列纵向长度的输出／输入比例 `1/k` |
| --- | --- | --- |
| 0 | 1.133975 | 0.881854 |
| 0.125 | 1.124054 | 0.889637 |
| 0.25 | 1.095724 | 0.912639 |
| 0.375 | 1.052750 | 0.949893 |
| 0.5 | 1 | 1 |

因此中央列的纵向长度收缩约 **11.8%**，左右边界位置固定；中心附近很小的横向长度也有同样的一阶比例。离开中心后，横向长度还涉及 `k` 随位置的变化，不能把整张图每一种长度都直接乘 0.881854。实际最终尺寸还经过轮廓提取与外接矩形，可能受边界和阈值影响。

也可以直接追踪一个输入点的去向。设其中心化横坐标为 `S`，则

\[
F(S)=a+\sqrt{1-(S/W)^2},\qquad
X=S/F(S),\quad Y=T/F(S).
\]

其中 `T` 是输入点的中心化纵坐标。这与上面的取样式互逆。对输入半幅等间隔 1,001 点核对，双精度计算中的最大归一化往返残差约 `1.11×10^-16`。这是代数核对，不包含 Rust 单精度、插值或物理误差。

## 4. 裁剪宽度这个 trick 有什么价值

**相同对象的等比例缩放不会改变相对校正强度。** 图像、裁剪和尺度一起放大 `s` 倍时，`f`、`r`、坐标也一起放大；`t` 和 `k(t)` 保持不变。忽略离散像素、插值和识别差异，长度像素数与每毫米像素数同时乘 `s`，毫米结果不变。这解释了为什么不能把它理解成“任意拿原图宽度冒充焦距”。

**裁剪让形变跟随果体的位置与范围。** 果体被扶正、居中后，中心收缩和边界锚定总施加在目标的相对位置。识别错对象、裁剪含过多背景、中心偏移或方向错误，会改变形变落在果体上的位置；这与项目负责人观察到的前置识别敏感性相符。

**它提供稳定的校正形状，而不是逐张恢复深度。** 固定 `f/W = r/W = 1` 后，分辨率不再是自由度；拍摄距离、视角和真实曲率也没有被单独估计。图像缩放不变性不能推导出拍摄距离不变性：移动相机会改变真实透视关系，即使最终裁剪尺寸被归一化。

## 5. 为什么可能与实测接近

下面是能够解释其作用方向的简化模型，不是对既有照片误差来源的定论。

假设参考物平面距相机为 `D`，一小块被测表面比它向相机凸出 `δ`，两者近似正对相机。按参考平面比例尺换算时，物体长度的放大率为

\[
m=\frac{D}{D-\delta}=\frac1{1-q},\qquad q=\delta/D.
\]

当前近似在中心的输出比例为 `c = 0.881854`。若原来有约 `1.133975` 倍的放大，即 `q ≈ 0.118146`，则 `c × m ≈ 1`，它恰能抵消这种放大。这为经验有效提供了一种几何解释：校正可能在一定拍摄条件下稳定补偿深度差。

用同一个局部模型改变 `q`，可看出边界：

| 假定深度差 `δ/D` | 按参考平面换算的原始倍数 | 再施加中心近似后的倍数 |
| --- | --- | --- |
| 0.05 | 1.0526 | 0.9283 |
| 0.118146 | 1.1340 | 1.0000 |
| 0.20 | 1.2500 | 1.1023 |

这些是假设情景下的计算值，不是项目实测误差。它们说明同一固定校正有可解释的适用范围，也说明不能据一组条件准确就证明任意距离都准确。反过来，不能因为公式不是完整物理模型，就否定已观察到的重复有效结果。

此外，真正的果体轮廓通常是曲面的切线投影，不能把上面局部表面公式直接当作全果长宽或体积的精确误差式。参考牌从原型中的位置改到纵轴平面，也可能改变原来被补偿的深度关系，须保留旧基线进行比较。

## 6. 不能从该公式推出什么

- **真实焦距和半径。** 默认 `r = W`，而图幅半宽为 `W/2`；`z0 ≈ 0.134W < r`，虚拟相机原点甚至位于所构造圆柱内部。这与来源的凹面图形投影相容，不能把每个参数按字面当作相机在真实果实外部的物理量。
- **弧长展开。** 这里没有将横坐标变为 `rθ` 的步骤，因此不是保持真实表面距离的圆柱展开；输出面积也不能直接解释为真实果皮面积。
- **双轴融合的物理唯一性。** 两次计算分别用 `W_roi` 和 `H_roi`，再从不同结果取长、宽和轮廓。这是组合近似，不是同一套相机内参下联合求出的三维曲面；两轴和旋转体积分的准确性需分别看参考测量。
- **任意视角、非对称形状或背面信息。** 归一化不会恢复不可见表面，也不会自行消除倾斜、遮挡、镜头畸变和模型形状差异。

仅将 `f` 改成 EXIF 换算的真实像素焦距也不构成修复。在当前构造下，中心比例为

\[
k(0)=1+\frac{r-\sqrt{r^2-(W/2)^2}}{f}.
\]

只增大 `f` 会减弱校正，但没有补齐真实半径、距离、主点、参考物平面等条件。旧文档所说“真实焦距通常导致欠校正”不应作为一般相机结论；它最多描述这组虚拟参数下改变一个量的效果。

还有一项与指标有关的区别：[fruitlet_counting.rs](../../src/pipeline/fruitlet_counting.rs) 在**未经过上述形变的扶正裁剪图**上选小果，再取最小面积外接矩形的边长。果体长宽／体积的校正和小果长宽不是同一条计算链；验证其中一项不能代替另一项。

## 7. 本次决定

保留现有计算作为经验基线，使用机器学习改善果体、参考物和果眼识别。评估时分别比较正确人工区域下的几何误差、自动识别增加的误差，以及最终可用率；不因为引入机器学习就同时更换全部几何，使变化来源无法判断。

本次没有运行照片批量评测、安装新模型或修改计算代码。已完成的是源头与历史核对、两条调用路径核对、归一化公式与逆式数值核对。新采集条件下的误差范围及体积、表面积、整果计数的独立准确性仍需相应实物依据。
