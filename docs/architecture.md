# 当前研究架构

本文面向开发者，记录整果侧面照片研究的目标、数据契约和验证边界。[Issue #21](https://github.com/AI4S-YB/pineapplehub/issues/21) 是学生采集与标注指南的唯一正文来源；仓库维护 [XML](annotation/label-studio.xml) 和正式配图，不维护学生指南镜像。

## 1. 六项同等优先的输出

1. 果体长度：沿冠芽端至果柄端方向的直线长度，不含冠芽和果柄。
2. 整颗最大横径：垂直上述纵向的最大直线跨度，不是任意照片投影宽度。扁果可以宽大于长，不能按数值大小交换。
3. 体积：目标果体的体积，不含冠芽、果柄。
4. 宏观表面积：目标果体外表面积，排除冠芽、果柄，不逐一累计细小纹理凹凸。
5. 中央代表性果眼长宽：赤道面中央 1–2 枚完整小果，按每枚自身最长直线跨度及垂直方向最大跨度测量；即使倾斜也用自身方向，不沿表面弧线。对象是相邻沟壑圈定的整枚小果，不是中央花盘或凹陷。这是代表性测量，不能宣称描述整颗果眼大小分布。
6. 整果果眼总数：同一颗果实含背面的人工总数，不是可见实例数量。

六项均为核心目标。体积和表面积的独立参考测量方法、设备、样本与精度阈值仍待确定，本轮没有为学生新增缺乏可靠操作方法的字段。

## 2. 数据来源、身份与划分

学生负责一颗果实选定一张原照片、可见区域和可靠实测；开发端从 Label Studio 取得原文件，内部关联任务、区域、实测及来源。已有品种、批次、日期等信息尽量关联，不增加学生技术编号、外部对应表、照片配对或重复上传。实测必须对应拍照时的同一对象和状态，不能将后期成熟果尺寸回填早期照片。

同一实物的重拍、重复图、裁剪和增强保持在同一数据划分。开发端负责转换、划分、训练和评估，学生不选择训练／测试集。田间受叶片遮挡的缺测可能集中于特定阶段，不能假设缺测随机发生。

已有真实任务、标注和草稿，不能再按空项目处理。配置切换需保留原图及原始快照，在导出副本验证转换和恢复后，协调者刷新并锁定生产记录：只改两类果眼标签名称、删除取消的 `target_fruit` 和 `reference_tag` 框结果；其他区域 ID、像素内容、图像尺寸、关联、已有数值、备注、状态和草稿身份均保留。不补造实测、不重新分配 ID、不清空试标、不另建正式项目。统计须从转换后的标注和草稿重建，重复转换无额外变化；有新增编辑先刷新验证，不覆盖。备份及真实标注保持私有。

## 3. 标注与测量接口

绿色 `完整可见果眼` 和蓝色 `部分可见果眼` 都是可辨认的独立实例，后者只描述可见部分；每枚独立区域。紫色 `fruitlet_uncertain` 不是果眼实例，也不是明确背景。青色 `fruit_body` 汇集全部可确认可见果体，包括分离小块、阴影和贴合组织，保留一条记录；不补画遮挡，不包括冠芽叶片、果柄、背景和外翘细长尖端。

先果眼／紫色，最后青色；青色不会替代或合并已有区域。所需目标包围范围由完整青色掩膜生成，包括分离小块，裁剪余量由开发配置。这是训练／评估接口，不代表推理时自动定位已经实现。

| 字段 | 含义与级别 |
| --- | --- |
| `tag_side_mm` | 任务级，实物牌黑色正方形边长，不含外白边 |
| `fruit_length_mm` | 任务级，固定纵向果体长度 |
| `fruit_max_width_mm` | 任务级，整颗最大横径 |
| `total_fruitlet_count` | 任务级，人工整果总数 |
| `fruitlet_long_diameter_mm` | 区域级，所选完整果眼自身长径 |
| `fruitlet_short_diameter_mm` | 区域级，与该枚长径垂直的最大宽径 |

所有字段可缺测，无默认值；尺寸正数、步长 0.1 毫米，计数正整数。两枚果眼分别保留原始值，由开发汇总。空值不生成伪零，也不删除区域；清空一项不得影响其他字段或其他果眼。输入精度不是测量精度。[临时 Number 构建配方](../deploy/label-studio-number/README.md) 对应 1.23.2 的空字符串问题，产品跟踪见 [#22](https://github.com/AI4S-YB/pineapplehub/issues/22)，通用修复见 [上游 #9989](https://github.com/HumanSignal/label-studio/pull/9989)。原生 View 根据所选完整果眼显示区域字段；正式镜像的保存、重开、导出验收仍是部署门禁。

数量级差异和极端值可提示复核，不能据统计自动改值或删除，也不能发现所有人共同填错单位。本轮不新增异常检测服务。标注完成状态不是测量有效性标签。

## 4. AprilTag 与物理边界

开发端复用现有 AprilTag 检测器取得编号和真实四角，学生不再画牌框、涂牌或点角。识别失败、多牌、目标对应不清交负责人。同编号可有不同打印尺寸，每张任务仍需对应实物牌的实测黑方边长，不从编号或 PDF 文件名推断。

当前 37 张原图曾用 AprilTag 3.4.5 检查，每张均有一个正确定位的 ID 0；这仅支持这些样本取消日常人工框，不证明无牌、多牌、遮挡场景的准确率。

牌放在果体最宽处侧边、靠近果体并面对相机，是让牌平面近似处于果体轴线附近的采集约定，仍需实测检验。牌、果体和果眼存在深度差；成功解码和准确分割不等于毫米测量准确，更不等于恢复三维形状。照片横向投影未必是整颗最大横径。不可见背面果眼、体积和表面积需要额外假设及独立参考数据。

## 5. 当前代码与研究接口

当前 Rust／WebAssembly 应用仍运行硬币和切面方案：[scale_calibration.rs](../src/pipeline/scale_calibration.rs) 检测 1 元硬币；[roi_extraction.rs](../src/pipeline/roi_extraction.rs) 依纹理选择 ROI（目标图像范围）；[unwrap_metrics.rs](../src/pipeline/unwrap_metrics.rs) 使用圆柱重投影及旋转体轮廓积分估计几何。[fruitlet_counting.rs](../src/pipeline/fruitlet_counting.rs) 用阈值、形态学和连通区域选代表果眼，以有效面积与果眼面积关系估整果总数。[fast.rs](../src/pipeline/fast.rs) 是并行计算路径；测量修改需同步两条路径。

[FruitletMetrics](../src/pipeline/mod.rs) 与 [CSV 导出](../src/export.rs) 已有长度、宽度、体积、代表果眼尺寸、表面积和总数字段，但其算法估计不是本次实测真值；旧 `major_length`／`minor_length` 命名也不能证明已符合新固定方向定义。[历史存储](../src/history/model.rs) 保留当前应用结果。本轮没有改变这些代码，没有实现 AprilTag 浏览器接入、训练数据转换器或 Burn 模型。

后续先验证人工掩膜与实测能否支持几何关系，再研究自动定位与实例分割。优先 Rust、Burn 和社区已有实现，用必要的小适配器连接数据；训练配置、转换和评估应可复现。尚未确定模型或运行时，不新增独立整图合格分类器。旧 #20 的分类器、硬币和切面流程属于历史方案，不是新采集流程。论文分数、参数量、文件大小或原生设备速度均不能证明浏览器内存、延迟、量化精度或 Burn 兼容性；模型选择须另做项目数据及目标设备验证。

[旧英文算法](algorithms/algorithm.md)／[旧中文算法](algorithms/algorithm_zh.md) 的正文保留，仍用于理解当前代码，旧精度与鲁棒性论述不自动成为新研究结论。

## 6. 监督与验证顺序

局部紫色不自动使整张图所有用途失效，但当前训练代码尚未支持忽略未知区域。不能把紫色或未标注背景菠萝当作明确负样本。先复核，按具体训练目标简单排除无法可靠监督的样本或用途，保留原图及可用信息；不为抢救含糊标注建设复杂私有框架。

验证分两阶段：先用人工区域和可靠实测评估几何假设，区分尺度、投影、深度和形状假设误差；再加入自动分割，测其额外误差。六类指标分别报告误差、参考值覆盖率和预测可用比例，再报告同时可用比例，不以完成率代替准确率。按品种、成熟阶段、果形、田间／采后条件检查偏差和缺测分布。体积与宏观表面积需独立参考测量，不能用同一公式的两次计算互证准确；整果计数须对照含背面的人工总数。

## 7. 研究依据及适用范围

- [澳大利亚 PI17000 项目报告](https://www.horticulture.com.au/globalassets/laserfiche/assets/project-reports/pi17000/pi17000-final-report.pdf)：报告的每条螺旋果眼数用于育种性状评价，不等同整果总数，不能直接替换本项目参考值。
- [UPOV TG/295/1 菠萝指南](https://www.upov.int/edocs/tgdocs/en/tg295.pdf)：供品种性状描述参考，不证明中央两枚能代表整体大小分布。
- [菠萝果眼形成的组织形态学观察](https://www.ahs.ac.cn/CN/10.16420/j.issn.0513-353x.2020-1093)：帮助区分花盘、宿萼及整枚小果；文中花盘宽度不能等同本项目按沟壑圈定的整枚小果宽度。

这些来源没有给出本项目六项输出的准确性验收结果。体积／表面积参考协议、样本数量、精度阈值及最终模型选型仍是后续研究问题。
